# Fixed Operations Contract

## Trust boundary

The public SelfHandler repository may run only on GitHub-hosted runners. The homelab production job
runs from an owner-controlled private repository and does not check out a pull request, branch name,
fork, or operator-provided repository. It consumes the exact reviewed default-branch revision selected
by the trusted workflow, validates same-run workflow identity plus immutable image digests and OCI
revision labels, and executes only the checksum-verified deployment bundle produced by that hosted
qualification job. GitHub attestations are not available for this user-owned private repository on
the selected GitHub Free plan.

## Fixed target

All routine commands resolve the following constants internally and reject conflicting effective
configuration:

```text
deployment_id: selfhandler-production
compose_project: selfhandler
root: C:\Homelab\SelfHandlerApp
local_origin: http://127.0.0.1:18080
public_origin: https://selfhandler.drpanya.uk
```

They never accept host, port, project, environment, profile, volume, or deployment-mode arguments.

## Operator entry points

### Routine release

**Entry point**: the input-free checked-in `./deploy.ps1` launcher, which sends an owner-authenticated
exact-SHA `repository_dispatch` to the trusted private operations repository.

**Inputs**: none.

**Behavior**:

1. Require the local public-repository `master` to be clean and exactly synchronized with
   `origin/master`, then dispatch that exact 40-character SHA with a fresh correlation identifier.
2. Qualify only that SHA on a GitHub-hosted runner and produce the release manifest and paired images.
3. Require all quality evidence and immutable digests.
4. Queue for the fixed homelab runner without checking out public source in that job.
5. Acquire the host mutation lock, create/upload/validate a recovery bundle, migrate once, replace,
   verify, and persist a crash-resumable pending journal.
6. Persist the trusted operations pointer, create and bind the required bootstrap post-auth recovery
   point, and use the trusted finalizer to atomically publish the active release and terminal result.
   An exact-identity retry resumes this phase without rebuilding, republishing, or remigrating.

The launcher has no parameters and does not deploy directly from the developer computer. There is no
moving-branch manual release action.

### Inspection

**Entry point**: `deployment/scripts/inspect-production.ps1`

**Inputs**: none.

**Output**: one non-secret structured report plus a human summary covering release digests, local and
public readiness, database/container health, expected volumes/networks, runtime isolation, capacity
status, latest validated backup age, and alert codes. Secret values and environment contents are never
printed.

### Scheduled/manual backup

**Entry point**: `deployment/scripts/backup-production.ps1`

**Routine inputs**: none. An internal reason set by trusted automation may be one of `predeploy`,
`scheduled`, `manual`, `pre-restore`, `bootstrap-baseline`, or `bootstrap`; arbitrary paths or target
identities are not accepted.

**Output**: encrypted `.age` recovery artifact, ciphertext checksum, authenticated manifest result,
off-host artifact reference, and plaintext-cleanup result.

### Restore drill

**Entry point**: `deployment/scripts/restore-production.ps1`

**Required inputs**: encrypted bundle path, operator-held age identity path, generated disposable
project name, and `-RecoveryMode Drill`. The project must match the validation prefix generated by the
drill launcher. Production project, networks, and volumes are refused.

### Real recovery

The same restore entry point requires all of:

- `-RecoveryMode Production`
- `-Target selfhandler-production`
- `-ConfirmTarget selfhandler-production`
- a valid pre-restore safety bundle unless the original host state is unavailable

These values authorize only the fixed target; they do not permit an arbitrary target. Automated tests
never supply Production mode. A bundle between 24 and 720 hours old additionally requires
`-ConfirmStaleBackup 'RESTORE selfhandler-production BACKUP OLDER THAN 24 HOURS'`; the operation records
that break-glass decision. Bundles older than the 30-day retention boundary or more than five minutes
in the future are refused. Drill mode always retains the 24-hour freshness limit.

## Exit behavior

| Exit class | Meaning | Production mutation permitted? |
|---|---|---|
| `0` | Requested operation completed and final verification passed | As defined by operation |
| preflight failure | Quality, dependency, health, capacity, identity, or isolation gate failed | No |
| backup failure | Snapshot, authentication, encryption, validation, cleanup, or upload failed | No |
| migration failure | Backup completed, migration did not complete | No application replacement; recovery artifact preserved |
| replacement failure | Candidate did not become healthy | Automatic paired-image rollback required |
| recovery required | Previous pair also failed verification | Workflow fails visibly; bundle and manual entry point reported |

No routine operation removes a production volume, runs `docker compose down -v`, invokes a database
seeder, runs a destructive migration rollback, or mutates the shared Caddy/router ingress.
