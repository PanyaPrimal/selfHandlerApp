02

Core user flows

Four loops carry the whole MVP. Two run every day (morning, evening); two are setup, done occasionally.

DAILY · AM Run the morning routine
Open app → Today → See today's items + 0% bar → Tap row = done → Completion + streak update → Optimistic PUT …/logs/{date}
DAILY · EDGE Skip a routine deliberately
Long-press row (mobile) / Skip control (desktop) → Choose “Skip”, optional note → Row struck, neutral — not a failure → Excluded from completion rate
DAILY · PM Close the day with an evening review
Today → “Close your day” → Mood · energy · stress · rating → Went well · improve · notes → Save PUT /daily-reviews/{date}
SETUP Create a routine & link it to a goal
Routines → New → Name · kind · daily/weekdays · time → Save → appears on Today → Goals → link routine (pivot)

07

Vue implementation notes

Vue 3 SPA in apps/web, Capacitor-wrapped for Android. One responsive codebase — the AppShell swaps rail ⟷ tab-bar at the breakpoint.

ROUTER ↔ API
/GET /api/today?date
/routinesGET·POST·PATCH /routines
routine donePUT /routines/{id}/logs/{date}
/review/:datePUT /daily-reviews/{date}
/goals linkPOST /goals/{g}/routines/{r}
STATE & PATTERNS
  • Pinia stores: useToday, useRoutines, useGoals — Today is the only one fetched on load.
  • Thin api/client.ts wraps the REST contract; CurrentUser header during dev.
  • Completion % & streaks are computed from routine_logs in the store — no daily_metrics table yet.
  • Done/skip toggles dispatch the upsert optimistically; rollback on reject.
  • Date in the route is the single source of truth for Today & Review.
  • One log per routine per date enforced by the unique key — PUT is idempotent.

texture dot: rgba(255,255,255,.055)
HOW TO WIRE IT
  • Move the colour tokens out of bare :root into :root[data-theme="light"] / ["dark"]. Radii, fonts, spacing, control metrics stay on :root — untouched.
  • Accent is a second axis: [data-accent] redefines --accent, --accent-soft, --accent-border and --focus-halo together — never one without the other.
  • useTheme() composable writes both attributes on documentElement; system subscribes to matchMedia('(prefers-color-scheme: dark)').
  • Persist to preferences.theme on the profile (alongside locale, units, tone). Mirror to localStorage only as a pre-hydration cache so the first paint isn't a flash.
  • Set the attribute in a tiny inline script in index.html before the app mounts — prevents the light-to-dark flash.
  • Reuse UiToggleGroup (scheme, motion), UiSwitch (texture, numerals), UiField (labels + helper). The accent picker is the one new control: UiSwatchGroup, radio semantics, 44px targets.
  • Saves are optimistic like the rest of the app — the theme applies on tap, PATCH /api/profile reconciles, failure rolls back with an inline notice.
